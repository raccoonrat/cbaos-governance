# 发布门禁（Release Gate）

## 门禁原则

1. **默认拒绝**：未显式勾选完成的项，视为未通过。
2. **自动化优先**：能进 CI 的检查不进人工表。
3. **证据可追溯**：每项应能链接到日志、报告或工单。

## 通用门禁（所有发布）

| ID | 检查项 | 证据类型 | 负责人 |
|----|--------|----------|--------|
| G-01 | 变更集与风险说明已填写 | PR / 变更单 | 作者 |
| G-02 | 代码评审完成（按分支策略） | PR 批准记录 | Reviewer |
| G-03 | CI 通过（构建、测试、静态检查） | CI 链接 | 作者 |
| G-04 | 安全基线无未处理例外（或已按政策批准） | 工单 / 例外记录 | 安全接口 |
| G-05 | 回滚方案可执行且已演练或在低风险窗口 | Runbook / 检查记录 | SRE |
| G-06 | 观测与告警就绪（仪表盘/告警规则已更新或声明无变化） | 链接 | SRE / 作者 |

## 带保证变更的附加门禁

若本发布包含或影响 **L3 保证**（见 `CLAIMS/claim_discipline.md`）：

| ID | 检查项 |
|----|--------|
| G-10 | 保证句式符合 `guarantee_grammar.md` |
| G-11 | 发布证据包已生成并链接（`EVIDENCE/release_evidence_pack_template.md`） |
| G-12 | 决策日志已追加（如适用，`EVIDENCE/decision_log_schema.json`） |

## 签署

发布负责人仅在 `release_checklist.md` 全部适用项完成后签署。
